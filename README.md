# ДолгКонтроль — локальный трекер долгов

Настольное приложение для учёта долгов, платежей, доходов и контроля графика выплат. Работает полностью офлайн, данные хранятся в локальной базе SQLite рядом с приложением и никуда не отправляются.

## Как запустить

Откройте `ДолгКонтроль.exe`. Откроется отдельное нативное окно приложения.

Приложение создаст рядом с `.exe`:

- `data/debts.db` — база данных долгов и платежей;
- `backups/` — автоматические и ручные резервные копии базы.

Если на компьютере недоступен WebView2, приложение автоматически откроется в браузере. Для работы нужен только Edge WebView2 Runtime; на актуальной Windows 10/11 он уже установлен.

> При первом запуске Windows SmartScreen может показать предупреждение, потому что файл не подписан цифровым сертификатом. Нажмите «Подробнее» → «Всё равно выполнить».

> В Диспетчере задач во время работы видно два процесса `ДолгКонтроль.exe`: загрузчик PyInstaller и само приложение. После закрытия окна они завершаются в течение нескольких секунд. Повторный запуск `.exe` не создаёт вторую копию — открывается уже запущенное окно.

## Возможности

- **Обзор** — общий остаток, выплаченная сумма, платежи за месяц, ближайший платёж и просрочки.
- **Долги** — ипотека, кредиты, карты, рассрочка и другие обязательства; сумма, ставка, срок, дата первого платежа, заметки.
- **График платежей** — помесячный календарь с разбивкой на основной долг и проценты; отметка оплаты и отмена оплаты.
- **Автоматический расчёт** — аннуитетный платёж или равные платежи для беспроцентной рассрочки; пересчёт остатка после оплаты.
- **История** — все совершённые платежи, фильтры по долгу и периоду, экспорт графика в CSV.
- **Доходы и распределение** — источники зарплаты и аванса с несколькими датами в месяце; напоминание в день выплаты, ввод фактической суммы и автоматический план: обязательные платежи на 30 дней (пропорционально всем платежам или по сроку), затем досрочное погашение долга с самой высокой ставкой, остаток на руках. Резерв можно ограничить и распределить между зарплатой и авансом.
- **Аналитика** — прогноз остатка, план и факт по месяцам, структура долгов по типам, детализация по каждому долгу.
- **Настройки** — тёмная и светлая темы, валюта, автоматические и ручные резервные копии с восстановлением, демо-данные, полная очистка.
- **Локальность** — сервер слушает только `127.0.0.1` на случайном свободном порту, внешний доступ отсутствует.

## Где лежат данные

```
D:\Приложение график платежей\
├─ ДолгКонтроль.exe
├─ data\
│  └─ debts.db          ← долги, платежи, доходы и распределения
└─ backups\             ← автоматические и ручные копии SQLite
```

**Перенос на другой компьютер.** Скопируйте `ДолгКонтроль.exe` и папку `data` целиком, сохранив их рядом друг с другом. Если перенести только `.exe`, приложение запустится с новой пустой базой — старые данные в него не попадут. Альтернативный путь: «Настройки» → «Экспорт в JSON», затем на новом компьютере «Импорт из JSON».

Резервные копии создаются автоматически после добавления, изменения, оплаты и удаления данных, а также вручную кнопкой «Создать». Хранятся только 5 последних копий, включая ручные; в «Настройках» можно посмотреть список, восстановить любую копию или удалить её. Перед восстановлением приложение само делает страховочную копию текущего состояния.

## Демо-данные

На пустой базе на главной странице доступна кнопка «Загрузить демо-данные»: 4 примера долгов (ипотека, автокредит, рассрочка, кредитная карта) с уже прошедшими платежами и два примера доходов — зарплата 7, 10, 12 числа и аванс 23, 25, 27 числа. Демо можно загрузить и из «Настроек». Перед вводом реальных данных очистите демо через «Настройки» → «Очистить все данные».

## Как распределяется доход

1. На 30 дней вперёд собираются все обязательные платежи. Если по какому-то платежу уже есть распределение с прошлого поступления, повторно он не резервируется.
2. Сумму резерва можно ограничить полем «Отложить на обязательные платежи». Например, с зарплаты 10-го закрыть только часть долгов, а платёж Игорю 25-го перенести на аванс 25-го. По умолчанию сумма делится пропорционально между всеми платежами: при 17 000 из 38 783 каждый платёж получает около 44% своей суммы. Если часть платежей уже была начата с прошлого поступления, следующее поступление сначала закрывает их, а остаток делит пропорционально между остальными. Режим «Сначала ближайшие по сроку» закрывает платежи по очереди. Непокрытые суммы попадут в блок «Перенесено на следующее» и будут автоматически зарезервированы из следующего поступления.
3. Остаток предлагается направить на досрочное погашение: сначала долг с самой высокой ставкой, затем следующий по ставке. Внутри одной ставки — меньший остаток.
4. Свободные деньги остаются на руках. Сумму досрочного погашения можно уменьшить прямо в форме — план и остаток пересчитаются.
5. Если дохода не хватает на обязательные платежи, форма покажет дефицит. Распределение носит рекомендательный характер и не меняет график автоматически: фактические платежи отмечаются в разделе «График платежей».

## Сборка из исходников

Требуется Python 3.10+ (проверено на 3.14) и Windows.

```bat
py -m pip install -r requirements-build.txt
py build.py
```

Готовый файл появится в корне проекта: `ДолгКонтроль.exe`.

Для запуска без сборки:

```bat
py app.py
```

Полезные ключи запуска: `--port 8765` (фиксированный порт), `--browser` (открыть в браузере), `--no-window` (только API-сервер), `--debug` (отладка WebView).

## Структура проекта

```
app.py                 точка входа, окно pywebview и нативные диалоги
backend/paths.py       пути к данным и ресурсам (работает и внутри .exe)
backend/db.py          SQLite, графики, платежи, доходы, распределение, аналитика, бэкапы, экспорт
backend/api.py         локальный HTTP API и раздача интерфейса
web/index.html         каркас интерфейса
web/styles.css         темы и компоненты
web/app.js             SPA: дашборд, долги, доходы, календарь, история, аналитика
web/chart.umd.js       Chart.js (локально, без CDN)
build.py               сборка .exe через PyInstaller
icon.ico               иконка приложения
```

## Технические детали

- База данных: SQLite с WAL и внешними ключами.
- Резервные копии: SQLite Backup API; автоматические снимки после изменений, хранятся только 5 последних копий вместе с ручными.
- API: стандартный `http.server.ThreadingHTTPServer`, только локальная привязка.
- Интерфейс: vanilla JS + Chart.js, без внешних CDN и сетевых запросов.
- Окно: pywebview + WebView2 (Edge), с запасным вариантом запуска в браузере.
- Сборка: PyInstaller onefile, ресурсы интерфейса распаковываются во временную папку, а данные всегда остаются рядом с `.exe`.
